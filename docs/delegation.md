# Delegation policy

Local development tooling. Not part of the published site, not referenced by any
route, and never cited as authorship anywhere in the catalog or its history.

`pnpm delegate` assembles the brief below, hands a task to another agent, and
reports back. This file is the brief's single source of truth — the dispatcher
reads it at run time, so editing this file changes what every delegate is told.

---

## Who does what

The split is by **what kind of wrong the work can go**, not by difficulty.

| Owner           | Work                                                                                                                                                   | Why                                                                                                                    |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------- |
| **In-house**    | Contracts, schema, ADRs, budgets, evidence and claims, phase planning, anything where the question is "is this honest?"                                | These fail by producing something plausible and untrue. No test catches that.                                          |
| **Codex**       | Bounded, specified, machine-checkable work: mechanical refactors, tests written to a stated contract, migrations, boilerplate, a second-opinion review | These fail loudly — `pnpm verify:all` catches them. Delegating work a test can judge is safe; delegating taste is not. |
| **Antigravity** | Interactive and visual work: UI iteration, layout, browser debugging, design exploration                                                               | It has no CLI (see below), so a human is in the loop regardless. That suits work judged by eye.                        |

**Never delegate:** changing a value in `config/budgets.v1.json`, writing or
amending an ADR, authoring project records or evidence, or anything that decides
what the portfolio claims about real work.

## Antigravity is not automatable

Antigravity 2.11.0 ships as an asar-packed Electron application with no CLI
entry point — no `bin/` shim, nothing registered on PATH, nothing in
WindowsApps. Unlike VS Code, which it otherwise resembles, there is no
`code`-style command to drive it headlessly.

So `--to antigravity` prepares the brief and opens the workspace. Pasting the
brief is one manual step, and that is the ceiling of what is possible today, not
a shortcut taken. If a CLI ships later, the dispatcher gains a real lane.

## How a delegated run is kept safe

1. Work happens on a `delegate/*` branch, never on `main`.
2. The sandbox is `workspace-write`. `--dangerously-bypass-approvals-and-sandbox`
   is never used.
3. Verification runs automatically afterwards, and the result is reported
   honestly whether or not it passed.
4. Nothing is merged or committed by the delegate. The diff is reviewed first.

# House rules for delegated work

_Everything below is sent verbatim to the agent. It is the part that stops a
cold agent from breaking rules it has no way to infer from the code._

## Hard rules — violating any of these makes the work unusable

1. **Never raise a budget to make something pass.** `config/budgets.v1.json` is
   reviewed configuration (PRD 12.2): "A visual effect that breaks a budget is
   removed, not excused." If something exceeds a budget, make it cheaper or stop
   and report. Changing a threshold requires an ADR and is not delegated.
2. **Never invent a metric, a measurement, a claim, or a piece of evidence.**
   PRD 0.10 and 12.2. If a number is not measured, it does not get written down.
   "Approximately", "roughly" and "should be" are not measurements.
3. **Never fix a failing test by weakening its assertion.** Fix the code. If the
   assertion is genuinely wrong, say so and explain why rather than editing it
   quietly.
4. **No AI attribution anywhere** — not in code, comments, commit messages,
   documentation, or content. No "generated by", no tool names as authorship.
5. **Do not add a dependency** without being told to. PRD 12.2 requires an ADR
   before a dependency lands, and ADRs are not delegated.

## Environment

- Windows, **PowerShell 5.1**. `&&` and `||` are parser errors — use `;` or
  `if ($?) { ... }`. No ternary, no `??`.
- **UTF-8 BOM breaks `JSON.parse` and CI rejects it.** `Out-File -Encoding utf8`
  and `Set-Content -Encoding utf8` both write a BOM on this shell. Write files
  with the editor, or
  `[System.IO.File]::WriteAllText(path, text, (New-Object System.Text.UTF8Encoding($false)))`.
  LF line endings only; CRLF breaks byte-identical builds.
- `pnpm` (not npm/yarn). Node 24, TypeScript 5.9.
- Useful commands: `pnpm typecheck`, `pnpm lint`, `pnpm test`,
  `pnpm test:e2e`, `pnpm measure:routes`, `pnpm catalog:build`,
  `pnpm verify:all` (the full chain).

## Conventions this repo actually holds to

- **Comments explain _why_, not _what_.** The prevailing style states the
  constraint or the failure a piece of code prevents, and cites the PRD or ADR
  section it comes from. Match it; do not add narration.
- Strict TypeScript: `erasableSyntaxOnly` is on, so **constructor parameter
  properties are not available**. `noUncheckedIndexedAccess` is on, so indexing
  yields `T | undefined`.
- `packages/engine` imports nothing from React, Next or the DOM. Keep it that
  way — PRD 7.4 depends on that boundary.
- The site must keep working with JavaScript disabled. Anything client-side is
  progressive enhancement layered over server-rendered markup.
- Tests assert on what a visitor can actually see, not on hidden markup.

## Definition of done

- `pnpm typecheck`, `pnpm lint` and `pnpm test` all pass.
- No budget changed, no assertion weakened, no dependency added.
- A short report: what changed, what was verified, and **anything left broken or
  uncertain, stated plainly**. An honest "this part does not work" is worth more
  than a confident summary that turns out to be wrong.
